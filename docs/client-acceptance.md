# クライアント検収

## 開発clientの構成と既存確認範囲

`.local/client-trial/mods`へ通常JAR、KFF配布JAR、対象MOD・関連依存、クライアント限定のJEIを揃えた。公開依存の版・取得URL・hash・sideは[dependency-manifest.json](dependency-manifest.json)、本アドオンのJAR hashは[verification.md](verification.md)を参照する。GatewaysとGameTest fixtureは試遊clientへ入れていない。

開発クライアントはMinecraft 1.21.1／NeoForge 21.1.252／Java 21で起動し、NeoForge版JEI 19.51.0.418の検出とJEI GUI atlas生成まで確認した。認証済みランチャーでの接続、画面の見た目、日本語表示、レシピ検索、実クラフトは未検収。この既存確認はGem Case機能の実操作を確認した結果ではない。工程2の試遊状況は下記チェックと[検証記録](verification.md)に記録する。

## 基盤の試遊手順

1. 認証済みランチャーでMinecraft 1.21.1／NeoForge 21.1.252の新しいinstanceを作る。既存instanceや保存ワールドを上書きしない。
2. `.local/client-trial/mods`のJARをコピーし、manifestとhashを照合する。`.local`はGitへ追加しない。
3. サンプルトークンの表示と、JEIで鉄インゴット1個＋紙1個から1個作るレシピを確認する。
4. 必要なら新規の専用サーバーへ接続し、実クラフトを確認する。基盤検証サーバーは通常JARと固定依存だけで127.0.0.1:25579へ起動確認済みだが、検証後は停止した。
5. client／serverの版、表示・接続・クラフトの観測結果を検証記録へ追加する。開発起動やGameTest成功を実操作の検収と置き換えない。

今回の検証サーバーはローカルの新規ワールド、online-mode=falseであり、アカウント認証を検証したものではない。一般公開するサーバー設定として使わない。

## Gem Case工程2の試遊手順

通常JARと固定依存を使い、新規client instance／新規worldで確認する。試遊に使うJARの配置場所は`.local/client-trial/mods`。今回の成果物のhashは検証記録と照合する。JEIは開発client限定とし、本体の必須依存にしない。

1. 上記の基盤試遊手順に従い、Minecraft 1.21.1／NeoForge 21.1.252／Java 21の新規instanceを作る。通常JARとmanifest記載の依存、JEIの版・取得元・hash・sideを照合する。既存worldを使わない。
2. 新規worldで創造モードまたは管理コマンドからGem Caseアップグレードを入手し、バッグへ装着する。recipeはない。仮texture・item名・タブ表示、日本語表示を確認する。
3. Apotheosisの標準Gem、追加component付きGem、非Gemを分け、画面のカーソル入力と通常slotへの左／右クリック、Shift移動を試す。専用へ入る数、通常収納へ回る数、残る数が入力元と一致することを確認する。
4. 純度別の表示、検索、スクロール、一個取出、最大stack取出、Shift取出、一括移動を試す。満杯のcursor／player inventoryでは保存数と出力が変わらないことを確認する。
5. 上限付近、未解決ID／純度、ロックpayload、二個目装着、中身あり取外し・交換を安全なテストデータまたはGameTestで確認する。通常操作で破損payloadを作らない。
6. バッグを設置／回収し、tier変更と再起動後に保存内容を確認する。必要なら新規の専用サーバーへ通常JARのみで接続し、clientとserverの版・接続結果を記録する。
7. 各項目を「確認済み」「未確認」「失敗」として観測結果付きで[検証記録](verification.md)へ記録する。起動やGameTestの成功を画面操作の確認として扱わない。

## Gem Case工程3の試遊手順

以下は連携機能の実操作で確認する項目。自動テストや起動成功だけではチェックしない。新規world／保存worldのコピーを使い、通常JARのhashと固定依存を照合する。

1. Gem Caseだけのバッグでは自動回収されないこと、有効なPickupを装着すると既存Pickupフィルタに従い専用→通常→余りになることを確認する。Pickup無効・フィルタ拒否・追加component付きGemも試す。
2. タブの「収納／転送設定」を切り替え、Deposit／Restockが初期OFFであることを確認する。両方向を別々に設定し、種類の翻訳名検索、未保管Gemの選択、純度の選択、すべて／指定／除外を試す。
3. 同じGemを通常収納と専用収納へ用意し、既存フィルタと専用フィルタを逆条件にする。Depositでは通常分が既存条件、専用分が専用条件に従うこと、移動数と残数の合計が保存されることを確認する。
4. Restockの専用設定がOFFまたは対象外なら専用へ入らないことを確認する。通常分の既存フィルタによる移動と、ON時の専用転送を分けて調べる。
5. 外部収納満杯、専用容量残り一個、部分空きで試し、未移動分が元に残ることを確認する。拒否後に空きを作って再操作し、後続操作が回復することも確認する。
6. 設定の保存、バッグ設置／回収、再起動後の保持を確認する。画面を閉じて別バッグへ切り替えたときに前の設定が混ざらないこと、同期中に編集できないことを確認する。

- [ ] Pickup併用／無効／拒否、専用優先、追加component保持
- [ ] 二方向の初期OFF・独立編集、三方式、種類検索・純度選択・未保管Gem
- [ ] 通常／専用に同じGem、逆のフィルタ条件、転送前後の数量保存
- [ ] Restock OFF／対象外の通常経路、ON時の専用経路
- [ ] 外部満杯・部分移動・残容量一個、拒否後の再操作
- [ ] 保存・再起動・バッグ切替、同期中／ロック中の編集不可
- [ ] 日本語表示・画面操作・認証済みclient接続

上位版の加工・材料枠・補充・上位化は工程4で扱う。


## Gem Case工程4の試遊手順

GameTestでの加工・変換と、下記の実client操作を区別する。通常JARと固定依存、開発限定JEIで新規worldまたはコピーを使う。

1. 創造モードから上位Gem Caseと専用変換itemを入手する。入手recipeと最終textureは工程5で扱う。上下合わせて一個だけ装着できることを確認する。
2. 下位へ標準Gemと転送設定を保存し、変換itemをcursorに持って装着した下位slotを右クリックする。Gem数量・転送設定が引き継がれ、cursorを一個消費し、新しい上位タブに六材料slotが現れることを確認する。
3. 加工viewへ切り替え、通常材料の左／右クリックとShift移動を試す。非材料・SWAP・drag・まとめ回収は保存を変えない。収納／設定viewまたはtabを閉じた状態では見えない材料slotへShiftで入らないことを確認する。
4. 同種類Gemの二個と実行時recipe材料を用意し、出力純度とserverが表示する必要材料を確認する。一回加工とShift加工（最大64回）の入力・出力・材料数を照合する。
5. 補充は初期OFFで、専用材料不足なら無変更。ON時は専用を先に使い、不足だけ同バッグ通常収納から補う。player inventoryや別バッグの材料は使わない。
6. 出力満杯・素材不足・同期途中・保存Locked時の拒否と、材料だけ正常な場合の回収を確認する。recipe reload後に新しい可否／コストへ更新され、古い画面の要求が実行されないことも試す。
7. 材料が残る上位は通常取り外し不可。材料・Gemを空にして取り外せること、補充設定・Gem・材料が設置／回収と再起動後も保持されることを確認する。

- [ ] 日本語／英語表示、六slotの配置と既存タブとの切替
- [ ] 中身入り下位の変換、cursor一個消費、数量／設定保持
- [ ] 材料クリック／Shiftと閉view時の通常経路
- [ ] 一回／Shift加工の数量保存、表示した必要材料との一致
- [ ] 補充OFF／ON、専用優先、同バッグだけから不足補充
- [ ] 満杯／不足／Locked／同期途中の拒否とreload後の更新
- [ ] 保存再起動、認証済みclient接続、pack共存、Windows
